# VELOUR

A premium minimal fashion ecommerce storefront (men's & women's apparel)
built with Next.js App Router, TypeScript, and a hand-written CSS design
system (no Tailwind).

## Stack

- Next.js (App Router) + TypeScript + React
- No Tailwind — `app/globals.css` holds the entire design system as CSS
  variables + hand-written responsive rules
- No backend — a mock async service layer (`lib/api.ts`) resolves data from
  an in-memory catalogue, designed to be swapped for a real API later

## Project structure

```
app/                    routes + layout.tsx + globals.css
components/             shared + page-level components (server by default)
lib/data.ts             BASE_PRODUCTS + CATEGORIES + PRODUCTS export
lib/generated-products.ts  regenerated by scripts/import-listings.mjs — never hand-edit
lib/api.ts              mock service layer — THE backend-swap seam
lib/store.tsx           cart context + localStorage persistence
lib/format.ts           money() helper
scripts/import-listings.mjs  CSV → catalogue import pipeline
incoming/               listings-template.csv, README.md, images/ drop folder
```

## Adding real products

See `incoming/README.md`. In short: copy
`incoming/listings-template.csv` to `incoming/listings.csv`, fill in rows,
drop photos into `incoming/images/`, then run `npm run import-listings`.

## Swapping the mock backend for a real one

Every page reads the catalogue exclusively through `lib/api.ts` — never by
importing `lib/data.ts` directly. To connect a real backend:

1. Replace the body of each exported function in `lib/api.ts`
   (`getProducts`, `getProductById`, `getFeatured`, `getNewArrivals`,
   `getTrending`, `getRelated`, `getSubcategories`) with a `fetch()` call (or
   a DB query) to your real endpoint/data source.
2. Keep the exported function names and return shapes identical — no page
   or component needs to change.
3. Once real inventory fully replaces the demo catalogue, switch
   `lib/data.ts`'s `PRODUCTS` export to `GENERATED_PRODUCTS` only (documented
   inline in that file). Keep `BASE_PRODUCTS` in the file — just disconnect
   it, don't delete it.

Cart state (`lib/store.tsx`) and checkout (`app/checkout/page.tsx`) are also
mocked — checkout is UI-only with dummy payment fields and a fake order
number, and would need a real payments/orders integration before going live.

## Commands

- `npm run dev` — local dev server
- `npm run build` — production build (must pass with zero type errors)
- `npm run start` — run the production build
- `npm run import-listings` — run the CSV → catalogue import pipeline

## Deploying free to Vercel

This app is stateless at runtime and has no server-side cron or database, so
it fits Vercel's Hobby tier with no configuration beyond the defaults:

1. Push this repository to GitHub (or your Git host of choice).
2. Import it in Vercel — it auto-detects Next.js, no build settings needed.
3. No environment variables are required for the current mock-data build.
4. The listings import script (`npm run import-listings`) is a local/dev-time
   step only — run it before deploying to bake generated products into
   `lib/generated-products.ts` and `public/images/products/`, which then ship
   as static output. It never runs on Vercel itself.
